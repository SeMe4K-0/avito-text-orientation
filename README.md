# Ориентация текстовых кропов: 0° или 180°

Тестовое задание Авито. Для каждого кропа с текстом предсказывается `p_180` — вероятность того, что текст перевёрнут. Метрика — `1 − Brier score`.

**Результат на платформе: `1 − Brier = 0.93891`**, файл [submission_teacher_t16.csv](submission_teacher_t16.csv).

Полное решение с пояснениями, картинками и графиками — в [solution.ipynb](solution.ipynb).

## Подход коротко

**Данные.** Обучающей выборки нет, метки получаю сам: беру заведомо ровный текст и половину примеров поворачиваю на 180°.

- *Синтетика*, 100 000 примеров на эпоху: строки из русской и английской Википедии плюс шаблоны объявлений (телефоны, цены, артикулы, модели), отрендеренные 71 семейством Google Fonts с кириллицей. Искажения подобраны по тому, что видно в тесте: градиентный фон, тени, обводка, дуга вывески, куски соседних строк, наклон, размытие, шум, JPEG, уменьшение до 14–110 px по высоте.
- *Рукопись*, 15 000 строк из Cyrillic Handwriting Dataset — реальные фотографии.

**Модели.**

| | модель | параметров | вход |
|---|---|---|---|
| учитель | ConvNeXt-Tiny (ImageNet) | 27.8 млн | 48 × 480 |
| студент | PP-LCNet ×0.5 (ImageNet) | 0.6 млн | 32 × 320 |

Учитель обучается на метках поворота, студент — на цели `0.5 · p_учителя + 0.5 · метка`. Замысел: в прод идёт крошечный студент. **На тесте студент дал 0.880, учитель — 0.936**, поэтому итоговое решение — учитель. Студент остался в репозитории как быстрый вариант.

**Калибровка.** Антисимметричный TTA `logit = (f(x) − f(rot180 x)) / 2` даёт точное `p(x) + p(rot180 x) = 1`. Температура 1.6 подобрана по результатам платформы — см. раздел ниже.

**Валидация.** Синтетика и рукописный тестовый сплит, бейзлайны — константа 0.5 и классификатор ориентации PaddleOCR.

| модель | синтетика | рукопись |
|---|---|---|
| константа 0.5 | 0.7500 | 0.7500 |
| PaddleOCR cls | 0.9112 | 0.7421 |
| студент без TTA | 0.9188 | 0.9354 |
| студент | 0.9336 | 0.9467 |
| **учитель** | **0.9867** | **0.9844** |

## Калибровка по лидерборду

Единственное место, где использована обратная связь платформы.

Валидация показывала 0.985, тест — 0.936: на тесте модель переуверена, а Brier наказывает уверенную ошибку вчетверо сильнее ответа 0.5. Я оценил, насколько именно. Пусть при логите с модулем `a` истинная вероятность правоты равна `sigmoid(a / T*)`. Тогда ожидаемый Brier при любой применённой температуре считается аналитически, без меток теста. По двум результатам платформы вышло `T* ≈ 1.6` (модель описала обе точки с точностью 1e-4); отправка с `T = 1.6` дала 0.93891 против предсказанных 0.93849.

Меток теста я не видел, но и слепым такой выбор не назвать: на скрытой выборке эффект мог бы оказаться слабее. Правильнее было бы получить поправку из валидации на реальных фотографиях печатного текста, которой у меня не было.

## Что не получилось

1. **Слабая валидация — главный дефект.** Синтетика использует те же шрифты, что и обучение, рукописный сплит участвовал в выборе чекпойнта, а реальных фотографий печатного текста (основная часть теста) в ней нет. Отсюда 0.98 на валидации против 0.94 на тесте, непойманный разрыв между учителем и студентом и температура в неверную сторону.
2. **Дистилляция не окупилась при таком бюджете:** 2 000 шагов студенту не хватило, его кривая на момент остановки ещё росла.
3. Я начинал собирать реальную валидацию: сбор фото вывесок и ценников с Wikimedia Commons, нарезку детектором PP-OCRv4 и отбор кропов, похожих на тестовые, через adversarial validation. Не успел скачать фото до дедлайна, в финальном решении этого нет.

## Как воспроизвести

```bash
git clone https://github.com/SeMe4K-0/avito-text-orientation
cd avito-text-orientation
python -m venv .venv && .venv/bin/pip install -r requirements.txt
# распакуйте выданный архив так, чтобы картинки лежали в test/test/images/
```

Дальше откройте [solution.ipynb](solution.ipynb) и выполните ячейки по порядку (`RUN_TRAINING = False` — берутся готовые веса из `artifacts/`). Или из терминала:

```bash
PYTHONPATH=src .venv/bin/python -m orient.pipeline submission
```

Инференс идёт на самом быстром доступном устройстве (MPS, CUDA или CPU): около 3 минут на Apple M4 Pro, около 45 минут на обычном CPU.

**Файл воспроизводится точно.** Прогон notebook даёт `submission.csv`, побитово совпадающий с отправленным `submission_teacher_t16.csv`. Сырые вероятности между запусками отличаются на 5e-7 (разный порядок суммирования в свёртках), но после округления до шести знаков строки идентичны. Оба файла лежат в репозитории.

Веса учителя весят 111 МБ и не помещаются в лимит GitHub на один файл, поэтому хранятся частями `artifacts/teacher.pt.part00`, `part01` — код собирает их автоматически.

Обучение с нуля — `RUN_TRAINING = True` или:

```bash
PYTHONPATH=src .venv/bin/python -m orient.pipeline teacher student evaluate submission benchmark
```

Для него дополнительно нужен рукописный датасет, см. [data/README.md](data/README.md). Все seed'ы зафиксированы, но обучение на другом устройстве может дать другие веса; отправленный файл воспроизводится из приложенного чекпойнта.

## Структура

```
solution.ipynb            решение с описанием, графиками и метриками
src/orient/
  paths.py                пути к данным
  download.py             скачивание шрифтов, корпусов и весов ImageNet
  text.py                 строки для синтетики
  synth.py                рендер синтетических кропов
  preprocess.py           кроп → серый холст фиксированного размера
  dataset.py              датасеты с поворотом и мягкими метками
  models.py               учитель, студент, антисимметричный TTA
  train.py                цикл обучения и предсказания
  metrics.py              Brier, ECE, калибровка температурой
  baselines.py            классификатор ориентации PaddleOCR как бейзлайн
  infer.py                submission, экспорт в ONNX, замер скорости
  viz.py                  картинки и графики для notebook
  pipeline.py             этапы решения целиком
artifacts/                веса, метрики, предсказания валидации, ONNX
data/                     шрифты и корпуса (см. data/README.md)
```
